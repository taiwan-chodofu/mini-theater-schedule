## 共通で必要になる基盤

### A. 和暦自由記述 → ISO 日付変換ユーティリティ

既存 `theater_schedule.py` の各 `parse_*` 関数は `YYYY-MM-DD` で返す前提。以下のような記法を日付リストに展開するヘルパを 1 つ作る:

```
"10月31日（土）"          → ["2026-10-31"]
"11月4日、10日～12日、14日" → ["2026-11-04", "2026-11-10", "2026-11-11", "2026-11-12", "2026-11-14"]
"12月1日〜12月27日"        → 期間内の全日 (または上映日のみ)
```

- 和暦の「月」が前後に連続する場合の継承
- 年またぎ (12月〜1月) の処理
- 「全休」「休館」などの除外語

### B. データモデル上の制約

既存の出力は「映画館 × 作品 × 上映日時」の 3 次元。特集企画型の 4 館は「作品 × 複数上映日時 × 回数」が中心で、定時上映ではなく「18:00〜」「14:30〜」のように個別指定が多い。既存モデルでそのまま食えるかの試算が要る (特集企画は時間指定がない告知もあり、`show_times=[]` を許容するかの判断)。

### C. 公式サイトのレンダリング

- アテネ・フランセ / 国立映画アーカイブ / 東京都写真美術館ホール → 静的 HTML (requests + BeautifulSoup で取れそう)
- アンスティチュ・フランセ東京 → JS rendering の可能性。Playwright フォールバックが必要かも
